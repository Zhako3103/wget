# Как устроен проект

Проект написан на Go, только на стандартной библиотеке, без внешних зависимостей. Это копия части функций wget.

## Файлы

| Файл | За что отвечает |
|---|---|
| `main.go` | разбор флагов, выбор режима, фоновый режим `-B` |
| `util.go` | общие функции: время, HTTP-клиент, разбор `--rate-limit`, ограничение скорости |
| `download.go` | обычная загрузка одного файла, `-O`, `-P`, прогресс-бар |
| `multi.go` | загрузка списка ссылок `-i` параллельно |
| `mirror.go` | `--mirror`, `-R`, `-X`, `--convert-links`, `--level` |
| `htmlparse.go` | поиск ссылок в HTML и CSS |
| `bg_unix.go`, `bg_windows.go` | отвязка фонового процесса от терминала (на каждой ОС по-своему) |
| `mirror_test.go` | тесты |

## Как работает каждая функция

**Обычная загрузка.**
1. Выводится время старта в формате `yyyy-mm-dd hh:mm:ss`.
2. Отправляется HTTP GET-запрос и выводится статус.
3. Если статус не `200 OK`, программа пишет ошибку и завершается с кодом 1.
4. Размер берётся из заголовка `Content-Length` и показывается в байтах и в МБ.
5. Имя файла берётся из последней части URL. Если указан `-O`, берётся оно.
6. Данные пишутся в файл кусками, а прогресс-бар обновляется на лету.

**Прогресс-бар.** Он перерисовывается в одной строке через `\r`, не чаще раза в 100 мс. Показывает скачанное в KiB или MiB (в зависимости от размера), процент, скорость и оставшееся время. Если вывод идёт не в терминал (например, в лог), бар не рисуется.

**`-P`.** Папка создаётся через `MkdirAll`. Символ `~` раскрываю сам, потому что оболочка не раскрывает его в записи `-P=~/...`.

**`--rate-limit`.** Значения `k` и `M` переводятся в байты в секунду. После каждого прочитанного куска считаю, сколько времени должна была занять передача при заданной скорости: `скачано / лимит`. Если реально прошло меньше, программа ждёт (`time.Sleep`). Так средняя скорость не превышает лимит. Проверка: 3 МБ при лимите 1M скачались примерно за 3 секунды.

**`-B`.** Программа запускает саму себя заново как дочерний процесс:
- вывод дочернего процесса перенаправлен в файл `wget-log`;
- на Linux процесс отвязывается от терминала (`Setsid`), поэтому закрытие терминала его не убьёт;
- в дочерний процесс передаётся переменная окружения `WGET_BG_CHILD=1`, по ней он понимает, что он «фоновый» и не должен снова запускать себя;
- родитель печатает `Output will be written to "wget-log".` и сразу завершается.

**`-i`.** Файл читается построчно (пустые строки и строки с `#` пропускаются). Дальше используются горутины и `sync.WaitGroup`:
1. Все запросы отправляются одновременно, ждём заголовки, выводим список размеров.
2. Все тела ответов скачиваются одновременно, каждое в своей горутине.
3. Печать защищена мьютексом, чтобы строки не перемешивались.
4. Файлы с одинаковыми именами получают суффикс `_2` и т. д., чтобы не затирать друг друга.

## Режим `--mirror`

Алгоритм: обход в ширину с очередью.
1. В очередь кладётся стартовый URL.
2. Берётся URL из очереди, скачивается и сохраняется в папку с именем домена.
3. Если это HTML или CSS, он разбирается и найденные ссылки добавляются в очередь.
4. Повторяется, пока очередь не опустеет.

Что важно знать:
- **Что ищем.** В HTML это атрибуты `href` и `src` у тегов `a`, `link`, `img` (плюс `script`, `source` и `srcset`). В CSS это `url(...)` и `@import`.
- **Защита от повторов.** Словарь `seen` хранит уже виденные URL, поэтому ничего не скачивается дважды и нет бесконечных циклов.
- **Относительные ссылки.** Преобразуются в абсолютные через `base.Parse(ref)` относительно адреса текущей страницы.
- **Какие ссылки куда ведут.**
  - Ссылки `<a>` ведут только на тот же сайт. Иначе скачали бы пол-интернета.
  - Картинки, стили и скрипты берутся с любых доменов (например, картинки Википедии лежат на `upload.wikimedia.org`). Они сохраняются в подпапку с именем того домена.
- **`-R=jpg,gif`.** Если путь заканчивается на `.jpg` или `.gif`, файл не скачивается.
- **`-X=/js,/assets`.** Если путь начинается с `/js` или `/assets`, он не скачивается и по нему не идёт обход.
- **`--level=N`.** Ограничивает глубину переходов по ссылкам. `0` значит только указанная страница с её картинками, стилями и скриптами.
- **Имена файлов.** Адрес `/` превращается в `index.html`. К страницам без расширения добавляется `.html`, к стилям `.css`. Запрос после `?` вшивается в имя файла. Слишком длинные имена укорачиваются с хешем.
- **`--convert-links`.** Выполняется вторым проходом, когда всё уже скачано:
  - ссылка на скачанный файл заменяется относительным путём к нему (`filepath.Rel`), так что сайт открывается офлайн;
  - ссылка на нескачанное (чужой домен, отброшенное фильтром) заменяется полным URL, чтобы продолжала работать онлайн.

## Ожидаемые вопросы и ответы

- **«Где рекурсия?»** Обход сделан не рекурсией, а циклом с очередью. Результат тот же, но нет риска переполнения стека на больших сайтах. Если спросят про рекурсию, ответ: «это обход графа ссылок, реализован итеративно (BFS)».
- **«Почему не пакет `html`?»** Пакета для разбора HTML-дерева в стандартной библиотеке нет (он в `golang.org/x/net/html`, внешний). Поэтому ссылки ищу регулярными выражениями, а пакет `html` из стандартной библиотеки использую для экранирования символов. Минус: регулярки не понимают весь HTML, например, ссылки, созданные JavaScript, не найдутся.
- **«Что не реализовано?»** FTP, докачка файла, учёт `robots.txt`, параллельное зеркалирование (в `--mirror` скачивание идёт последовательно).
- **«Как проверяли?»** Юнит-тесты (`go test ./...`) и ручной запуск против локального HTTP-сервера: загрузка, `-O`, `-P`, 404, лимит скорости, `-B`, `-i`, зеркало с фильтрами и конвертацией ссылок.
- **«Почему `text file busy`?»** Это было совпадение имён: адрес заканчивался на `/wget`, и программа пыталась перезаписать собственный запущенный файл. Решение: назвать бинарник иначе (`mywget`).

Если хотите, могу составить список вопросов, которые обычно задают на проверке, и потренировать вас на ответах.
